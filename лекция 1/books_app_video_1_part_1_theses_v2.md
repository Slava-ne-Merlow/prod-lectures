## 2. Как устроено приложение?

- Приложение помогает решать задачи: общаться, делать покупки, вести список книг.
- Клиент непосредственно взаимодействует с пользователем: отображает данные, реагирует на действия, отправляет запросы.
- Бэкенд выполняет логику приложения, работает с данными, проверяет права доступа и возвращает результат.
- Клиенты бывают веб-, мобильными и настольными. Могут обращаться к одному бэкенду.
- Плюсы разделения: интерфейс под каждое устройство, общие данные и правила на сервере, отдельная разработка обеих частей.

-----

## 3. Как договориться фронту и бэку?

- Контракт API — договорённость о запросах и ответах для параллельной разработки.
- API определяет, какие запросы может отправлять клиент и какие ответы получать.
- Согласуют передаваемые данные и поля, ответы при успехе и ошибке.
- Фронтенд работает с тестовыми данными, пока бэкенд реализует серверную часть. Затем их соединяют.

-----

## 4. Из чего состоит HTTP-запрос?

- HTTP — протокол обмена запросами и ответами. HTTPS защищает соединение шифрованием.
- Разбираем метод, адрес и тело — без утверждения, что это полный состав запроса.
- Метод — какое действие клиент ожидает от сервера.
- URL — адрес запроса. Адрес сервера указывает, куда отправлять запрос, путь — к какой части приложения обращаться.
- Localhost — обращение к своему компьютеру. Порт помогает направить запрос нужному серверу.
- Body — передаваемые данные. JSON — текстовый формат: объекты с полями, списки, строки, числа и другие значения.
- Тело нужно не всегда: GET обычно отправляют без него.

-----

## 5. Какие бывают HTTP-методы?

- GET — получение данных; не должен изменять состояние сервера.
- POST — передача данных для обработки, часто для создания объекта.
- PUT — полное новое состояние объекта.
- PATCH — частичные изменения.
- DELETE — удаление объекта по указанному адресу.
- Другие методы существуют, но здесь их не разбираем.
- Метод и путь рассматриваем вместе: один путь с разными методами может вести к разным обработчикам.

-----

## 6. Как выглядит HTTP-ответ?

- Сервер отправляет ответ после обработки запроса.
- Статус-код сообщает результат обработки.
- Тело содержит данные для клиента, часто в JSON; иногда оно пустое.
- Клиент использует полученные данные в интерфейсе.

-----

## 7. Какие бывают HTTP-статусы?

- `1xx` — информационные ответы.
- `2xx` — успех.
- `3xx` — перенаправления и некоторые другие действия.
- `4xx` — проблемы с запросом клиента.
- `5xx` — ошибки на стороне сервера.
- **200 OK** — запрос успешно выполнен.
- **201 Created** — новый объект создан.
- **404 Not Found** — запрошенное не найдено.
- Пустой список может вернуться с 200: в списке нет элементов, но запрос выполнен. Это отличается от запроса конкретной несуществующей записи.

-----

## 8. Как сервер обрабатывает запрос?

- По методу и пути приложение выбирает функцию-обработчик.
- Обработчик выполняет действие и готовит ответ.
- `GET /users` — список; `GET /users/42` — конкретный пользователь; `POST /users` — создание.
- Сочетание метода и пути — endpoint, или ручка.
- Выбор обработчика поручаем FastAPI — инструменту для создания API на Python.

-----

## 9. Как написать первый endpoint?

- Создать объект приложения FastAPI.
- Описать функцию-обработчик и связать её с запросом через декоратор.
- `app.get` задаёт GET, строка в скобках — путь. FastAPI вызывает функцию при подходящем запросе.
- Словарь или список из функции преобразуется в JSON. При успешном выполнении по умолчанию — 200.
- Чтобы принимать запросы, приложение нужно запустить.
