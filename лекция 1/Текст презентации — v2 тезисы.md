## 2. Как устроено приложение? · 35 секунд

- Приложение решает задачи пользователя: общение, покупки, каталог книг.
- Клиент отвечает за непосредственное взаимодействие с пользователем. Может быть веб-клиентом или мобильным приложением.
- Бэкенд обрабатывает запросы, работает с данными и проверяет права доступа.
- Обмен: действие пользователя → запрос → обработка на сервере → ответ → обновление интерфейса.
- Зачем разделять: разные клиенты используют общие данные и логику; интерфейс и бэкенд можно развивать отдельно.

-----

## 3. Как договориться фронту и бэку? · 25 секунд

- Чтобы разрабатывать параллельно, заранее согласуют контракт: методы и пути, передаваемые поля, формат ответов и статусы.
- Фронтенд использует тестовые данные согласованного формата, пока бэкенд пишет обработчики.
- API — доступные операции и правила обращения к ним.
- REST — подход к организации взаимодействия. Одна привычная практика HTTP API: путь обозначает, с чем работаем, метод — что делаем. REST шире правил именования путей.

-----

## 4. Из чего состоит HTTP-запрос? · 40 секунд

- HTTP — правила обмена запросами и ответами; HTTPS защищает соединение шифрованием.
- Разбираем несколько важных частей запроса: метод, URL и тело.
- Метод — какое действие клиент просит выполнить.
- URL — полный адрес запроса: протокол, адрес сервера и путь. Путь указывает, к какой части приложения обращаемся.
- Localhost — обращение к своему компьютеру. Порт указывает, где сервер принимает соединения.
- Body — передаваемые данные, например имя и возраст при создании пользователя. JSON — текстовый формат данных. GET обычно отправляют без тела.

-----

## 5. Какие бывают HTTP-методы? · 40 секунд

- GET — получение данных; не должен изменять состояние сервера.
- POST — передача данных для обработки; часто — создание объекта.
- PUT — полная замена состояния объекта. PATCH — частичное изменение.
- DELETE — запрос на удаление объекта.
- Есть и другие методы, например HEAD и OPTIONS. Здесь достаточно назвать их.
- Метод сам не выполняет действие: его реализует код обработчика. Поведение должно соответствовать назначению метода.

-----

## 6. Как выглядит HTTP-ответ? · 20 секунд

- В ответе сейчас важны статус и тело.
- Статус сообщает результат обработки запроса.
- Тело содержит данные для клиента, часто в JSON. Иногда тела нет.
- Клиент использует полученные данные, чтобы обновить интерфейс.

-----

## 7. Какие бывают HTTP-статусы? · 40 секунд

- Первая цифра обозначает группу: `1xx` — информационные; `2xx` — успех; `3xx` — перенаправления; `4xx` — ошибки клиента; `5xx` — ошибки сервера.
- 200 OK — запрос успешно выполнен.
- 201 Created — новый объект создан.
- 404 Not Found — запрошенное не найдено.
- Пустой список может быть успешным ответом с кодом 200: отсутствие элементов само по себе не ошибка.

-----

## 8. Как сервер обрабатывает запрос? · 25 секунд

- Приложение выбирает обработчик по HTTP-методу и пути.
- Endpoint, или ручка, — точка обращения к бэкенду; обработчик — функция, которая выполняет работу и готовит ответ.
- Один путь с разными методами может вести к разным обработчикам.
- FastAPI берёт на себя выбор обработчика и формирование HTTP-ответа.

-----

## 9. Как написать первый endpoint? · 20 секунд

- FastAPI — инструмент для создания бэкенда на Python.
- `app = FastAPI()` — создаём приложение.
- `@app.get("/")` — связываем метод GET и путь / с функцией.
- Функция возвращает словарь, FastAPI отправляет его в JSON. Подробный разбор кода — в практике.
